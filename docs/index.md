# Ottor1 的文档建站实践

欢迎来到我的个人技术文档网站。我使用 GitHub 账号 **Ottor1** 参与开源软件课程实践，在这个项目中学习 Markdown 写作、Python 环境管理和静态文档自动部署。

我希望把一次建站过程整理成可以回看和复用的记录：文件如何组织、命令到底使用哪个 Python、安装失败时怎样读报错，以及修改后的内容如何出现在网页上。源码保存在 [Ottor1/my-docs](https://github.com/Ottor1/my-docs)。

## 我的实践从哪里开始

这次实践中，我的电脑已有 Anaconda 提供的 Python 3.13.9，而课程示例使用 Python 3.12。我先确认版本和解释器位置，再使用项目内的 `.venv` 安装构建依赖。目前，本地依赖检查和严格构建都已通过，也已经能打开网页查看内容。

安装过程中，我遇到了清华镜像下载 `requests` 时的 SSL 连接中断。换用官方 PyPI 源后安装成功。这让我开始把报错拆开来看：先确认出问题的步骤，再检查解释器、依赖或网络连接，处理后重新构建验证。

## 我对发布过程的理解

```text
修改 docs/ 中的 Markdown
        ↓
在本地运行 mkdocs build --strict 并预览
        ↓
提交并推送到 main
        ↓
GitHub Actions 生成并上传 site/
        ↓
GitHub Pages 发布网站，访问页面核对变化
```

`docs/` 是我维护的文档源码，`site/` 是工具生成的网页。以后修改内容时，我会编辑 Markdown，再重新构建；发布是否成功，则需要结合 Actions 运行结果和实际网页一起检查。

## 这次最有用的两条经验

1. **让命令明确指向项目环境。** 使用 `.venv/Scripts/python.exe` 运行模块，可以清楚地知道依赖安装在哪里、构建使用哪个解释器。
2. **给排错留下可验证的结果。** 安装成功后继续做依赖检查和严格构建，网页打开后还要检查导航、表格、代码块与链接。

更完整的过程和体会见[关于页](about.md)，可复用的命令见[使用指南](guide.md)。
